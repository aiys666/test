# 印尼经分周报自动化优化方案

---

## 一、当前问题

### 现状流程（每周一，2-3小时）

1. 手动跑 4 条 Presto SQL，等待结果（15-20min）
2. 复制粘贴到 Excel 3 个数据源 Sheet（10min，4.4万行+9.5万行经常卡死）
3. 刷新透视表/公式（5min）
4. 逐项核对数据（10min）
5. 手写首贷文字分析（30-60min）
6. 另存版本号发送（5min）

### 核心痛点

| 痛点 | 原因 | 影响 |
|------|------|------|
| **内存爆炸（99%）** | 数据源Sheet共14万行×87列=1200万单元格，openpyxl每个Cell占100-150字节，总内存~1.2GB | 脚本跑不动，Excel也卡 |
| **4.4万+9.5万行没必要** | 周报和首贷分析只看周度/月度聚合数据，87列明细大部分列没被引用 | 粘贴慢、刷新慢、文件大 |
| **手工重复操作** | 每周同样的SQL→粘贴→刷新→写文字 | 占2-3小时，无创造性价值 |
| **首贷文字纯手写** | 每周根据指标数据人工组织文字 | 最耗时的部分（30-60min） |

### 数据源Sheet规模

| Sheet | 行数 | 列数 | 单元格 | 内存占用 |
|-------|------|------|--------|---------|
| 数据源(进件) | 44,505 | 87 | 387万 | ~400MB |
| 复贷数据源 | 94,958 | 87 | 824万 | ~800MB |
| 投放数据源 | 1,495 | 12 | 1.8万 | ~2MB（没问题） |

## 三、优化方案

### 方案1：SQL做聚合，不导明细（推荐，最彻底）

**思路**：把 `SELECT *` 改成 `SELECT ... GROUP BY`，返回几百行而不是几万行。

**改动前 vs 改动后**：

| | 改动前 | 改动后 |
|--|--------|--------|
| SQL2(进件) | `SELECT * FROM ... LIMIT 100000` → 4.4万行×87列 | `SELECT app_week, app_month, product_tag, grant_strategy, SUM(if_app), SUM(if_external_3_passed), SUM(in_confirm_cnt_final), ... GROUP BY 1,2,3,4` → ~500行×10列 |
| SQL3(复贷) | `SELECT * FROM ... LIMIT 100000` → 9.5万行×87列 | 同上，加 `new_old_model_loop, is_reloan2` 等维度 → ~300行×10列 |
| 内存占用 | ~1.2GB | **~5MB** |
| 写入耗时 | 5-10分钟 | **30秒** |
| Excel文件大小 | 30+MB | **<2MB** |

**需要做的**：
1. 确认周报/首贷分析实际用了哪些维度和指标列（app_week, app_month, product_tag, grant_strategy 等）
2. 把 SELECT * 改成 SELECT 维度 + SUM/指标
3. Excel 数据源 Sheet 从 87列×14万行 改成 10列×几百行
4. 周报 Sheet 的公式/透视表重新指向新的聚合数据源（字段名可能变了，需要微调）
5. 如果偶尔需要钻取明细，单独跑一次原始SQL导CSV备用

**优点**：最彻底，内存问题根治，脚本跑一次30秒
**风险**：需要确认引用的维度列，公式可能要微调
**适用**：如果你确定周报只看聚合数据

---

### 方案2：明细导CSV，Excel只存聚合（折中方案）

**思路**：Python脚本做两件事——明细导CSV（轻量），聚合结果写Excel。

**流程**：
```
SQL查询 → pandas读取 → 
  ① df.to_csv('进件明细_20260629.csv')   (几秒完成，内存极低)
  ② df.groupby().agg() → 聚合结果 → openpyxl写入Excel数据源Sheet (几百行)
```

**需要做的**：
1. SQL不改，仍然 SELECT *
2. 脚本里加 `df.to_csv()` 把明细导出
3. 加 `df.groupby([...]).agg({...})` 做聚合
4. 聚合结果写入 Excel 数据源 Sheet（几百行）
5. 周报引用聚合 Sheet
6. 需要查明细时，打开 CSV 文件

**优点**：明细数据不丢，Excel不背大包袱，内存50MB以内
**风险**：CSV文件存磁盘，不方便Excel内直接钻取
**适用**：如果你想保留明细数据备查

---

### 方案3：换xlsxwriter写明细（治标不治本）

**思路**：xlsxwriter是流式写入，内存恒定~50MB，但只能新建文件不能修改已有文件。

**流程**：
```
SQL查询 → xlsxwriter新建数据源Excel → 周报Excel用公式=INDIRECT引用数据源Excel
```

**需要做的**：
1. 把周报拆成两个文件：`数据源.xlsx`（xlsxwriter新建写入）+ `周报.xlsx`（展示+公式）
2. 周报Sheet用外部引用公式如 `='数据源.xlsx'!数据源(进件)!A2`
3. 每周只更新数据源文件，周报文件自动联动

**优点**：不改SQL，不改Excel结构，内存问题解决
**风险**：两个文件联动复杂，Excel外部引用不稳定，写入9.5万行仍需5-8分钟
**适用**：如果你不想改任何东西，只解决内存问题

## 四、推荐路径

**先做方案1，如果不确定维度就先做方案2。**

| 步骤 | 内容 | 预计时间 | 效果 |
|------|------|---------|------|
| Step 1 | 确认周报/首贷分析引用了哪些维度列 | 30min | 明确聚合SQL该怎么写 |
| Step 2 | 改写SQL2/SQL3为聚合版本 | 15min | 数据量从14万行→800行 |
| Step 3 | Excel数据源Sheet结构调整为聚合表 | 30min | Sheet从87列→10列 |
| Step 4 | 周报/首贷分析公式微调 | 30min | 引用新聚合字段名 |
| Step 5 | 脚本测试 | 15min | 跑通全流程 |
| **合计** | — | **~2小时** | **每周一从2-3h→15min，内存从99%→5%** |
