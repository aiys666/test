## 一、两类临额的本质区别

| 维度 | 在线临额 | 离线临额 |
|---|---|---|
| 触发时点 | 用信时（点借款按钮后毫秒级决策） | 用信前，营销系统每日 20-21 点批量圈客 |
| 客户感知 | 用信成功页弹窗，全用或不用（10秒默认不用） | 被动到账，有效期内随借随用 |
| 额度变更事件码 | **C010** | **C015**（标准批量）/ C013（人工补单，非常规口径） |
| 名单粒度 | biz_id 级实时进件 | MID 级名单 |
| 有效期 | 3 天（1379 节点实落） | 5 天（1505 节点实落） |
| 发放额算法 | 占用主额向下取整 20 档 × type 比例，四舍五入 50 档 | 节点 1504 推荐额，与 C015 匹配率 86.6% |

**关键恒等式**：`contract_amount = risk_credit_limit(MAIN冻结) + temp_grant_amount(TEMP使用)`，逐笔成立（全量匹配率 99.6~100%）。

## 二、在线临额完整决策链（已全链路验证，命中率 99.94%）

```
C009 授信落账(=1067.credit_amount)
  → C002 申请时主额提额(external_id=mid_ts合成串)
  → C003 主额预授权(external_id=本biz, 对总额度授权≠实际支用)
  → 1522 用信评分
  → 1523 fd_use_creditamount_type (type1/2/3; type4不触发)
  → 1386 临额发放弹窗决策(temp_credit_amount_issue_tag; createtime=发放时刻)
  → 1379 决策树理论算额(占用主额floor20×比例, 有效期3天)
  → 857  最终弹窗发放额(temp_credit_amount)
  → C010 客户确认领取(create_time=使用时刻; 发放→使用中位间隔92秒)
```

- **type 比例**：type1 在 V5_2=50% / V5_3=60%（仅由策略版本决定，无时间漂移）、type2=40%、type3=20%
- **发放 ≠ 使用**：1386 的 tag=1 只是弹窗展示，仅 46% 真正产生 C010
- **主额占用补全**：used_detail 批次延迟造成 1.36% 缺失，用 `合同金额 − 临额使用额` 恒等式补全
- **算额底数** = C003 冻结时刻的本笔主额占用（used_detail MAIN，缺则补全）

## 三、离线临额链路

```
每日20-21点批处理: 1504 推荐额(mid级, biz为空) + 1505 有效期=5天
  → C015 批处理落账事件(与1504时刻差≈0)
  → 有效期内随借随用(仅约16%放款真正消耗临额)
```

## 五、核心业务结论（按主题）

### 临额效果
- 有临额客户质量显著优于无临额：授信通过率 100% vs 23-28%，放款率 95-97% vs 74-77%，件均近 2 倍
- 离线临额实际使用率极低（仅 16% 放款消耗），核心价值是提升合同件均（+8-13%）而非笔数
- 混合（在线+离线）组逾期风险最高：同档位较纯离线组高约 6pp

### 坏账影响
- 8/10 周坏账上升主因：离线临额坏账率+5.08pp（贡献+2.69pp）+ 在线临额 V5_3 上线（率效应+2.12pp）
- V5_3 扩额下沉致高风险客群（g6_8、g9p）坏账显著升高；切回 V5_2 的改善来自客群选择效应
- 收缩临额不消除整体风险，仅将风险转移至无临额长尾客群
- 同评分段内无临额组坏账显著高于临额组 → 临额政策在各评分段均筛选到相对优质客户

### 占用与残留
- 临额残留 bug（已结清未解冻）仅存在于 2026 年 2-3 月 TEMP 维度，4 月起已修复，全量影响 111 笔/40,120 比索
- 跨笔时间重叠的额度覆盖风险几乎全部来自离线批次；在线侧冲突率仅 0.1%
