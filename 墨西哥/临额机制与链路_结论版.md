# 墨西哥临额（TEMP Limit）—— 结论版（决策摘要）

> 配套文档：《临额机制与链路汇报.md》（机制 / 口径 / 案例全量）。本文只讲四件事：**结论 → 依据 → 怎么调 → 调完会怎样**。
> 读法：正文中「a / b / c / d」形式的多值，除注明外均按 **2026-07 / 08 / 09 / 10（10 月为 1-15 日半月）** 顺序排列。
> 数据窗口：复贷老客放款 `tenant='yawey' and is_reloan='old' and if_issue=1`，2026-07-01 ~ 10-15（58,927 笔）；部分结论用 08-19 ~ 10-05 窗口。金额单位：**比索（MXN）**。

---

## 一、一句话结论

**临额本身不是坏账来源，它是"客群筛选器"；当前坏账上行来自「客群下沉 + 风险向无临额长尾转移」，叠加在线 V5_3 扩额在低分档的过度下沉。额度侧真正的硬约束只有两个：C003 主额预授权、复贷主额单笔 1 万。**

---

## 二、核心结论（结论 → 依据 → 怎么调 → 预计反馈）

### 结论 1｜1 万合同上限是"纯主额"的产品上限，只有在线临额能突破，且在逐月放大

**依据**
- 复贷主额单笔**硬顶 10,000**：全量 **0 笔超 10,000**、114 笔正好卡顶；无临额组"合同正好 = 1 万"的笔数（7/8/9/10 月）为 **0 / 6 / 46 / 27 笔**、"合同 > 1 万"的四个月均为 **0 笔** → 1 万是纯主额上限。
- **在线临额在主额池外叠加**，是唯一突破通道：溢出合同（7/8/9/10 月）**3 / 22 / 51 / 36 笔**，占比 **0.11% / 0.49% / 1.20% / 1.54%**；溢出金额 **3,600 / 37,762 / 113,212 / 77,312 比索**（10 月为半月，绝对量已接近 9 月），**逐月放大**。
- **离线临额与主额同池补差**，上限就是 1 万：4,960 笔已用 **0 笔突破**。
- 溢出笔主额并非都顶格：主额分布 10,000 占 37.5%、8,000 占 30.4%、7,000 占 16.1%——只要 `主额 ×(1+在线比例) > 10,000` 就溢出。

**怎么调**
1. 先给 1 万定性：**若 1 万是有意的主额风险上限**，则在线临额的"池外叠加"正在绕过它 → 给「主额 + 在线临额」设**合同级封顶**（建议 **≤ 12,000**，即在线叠加封顶 2,000）。
2. 若只是历史遗留 → 不动逻辑，但在报表上**单列"在线溢出合同"**，纳入风险监控。

**预计反馈**（口径明确的为实测，带"≈"为结构近似）
- 按当前溢出结构，合同级封顶 12,000 后，**每月约削减 4~6 万比索溢出敞口 ≈**（16,000 类砍 4,000 / 14,000 类砍 2,000 / 12,800 类砍 800）。
- 影响面很小：每月约 20~30 笔、占在线已用笔 **≤ 1.5%**，对整体放款规模几乎无感知。

---

### 结论 2｜离线临额被 1 万硬截断，每月约 100 笔、23~24 万比索额度被砍

**依据**
- "被压掉"口径 `greatest(主额 + 持有离线额 − 10,000, 0)`，按 7/8/9/10 月依次：**101 / 106 / 106 / 64 笔**，合计 **237,639 / 232,970 / 243,255 / 158,096 比索**，占离线已用 **2.1% → 3.9%**（逐月上行）。
- 离线每月"撞顶"（补到 1 万即止，7/8/9/10 月）**87 / 96 / 82 / 49 笔**，四个月 **0 笔突破**。
- 离线临额幅度是**单一参数可调**：发放额 = 主额度 × **10% / 20% / 30%** 三档（`temp_limit_tag` 后缀 `_1/_2/_3` 区分），公式含 200 保底、取整到 50、且不低于已用临额；全量 120,488 行公式回算命中率 **96.1%**。

**怎么调**
1. **先定性**：离线临额的业务目的是"补额度促用信"，1 万截断正在稀释这个目的。
2. **若要释放**：把离线的合同上限与主额 1 万上限**适度解耦**（如离线客户合同封顶放宽到 12,000），或对"主额已顶格"的客户**优先改投在线临额**（在线可破 1 万）。
3. **若要控风险**：维持 1 万截断，但把"被砍掉"的额度记入额度机会成本台账。

**预计反馈**
- 放宽到 12,000：**释放 ≈ 23~24 万比索/月**额度（约等于离线当月发放额的 7~8%），落到约 100 笔/月的老客身上；**代价**是同步增加同等敞口，需按这些客户的历史 t0 单独评估。
- 维持现状：额度损失确定可控（<4% 的离线已用），无新增风险。

### 结论 3｜坏账上行 = 客群下沉 + 风险向无临额长尾转移，不是"临额发的"

**依据（结构分解，周度）**
- **8/10 周**上行主因：① 离线临额坏账率 **+5.08pp**（贡献 **+2.69pp**）；② 在线 V5_3 上线（渗透率 13.2% → 22.0%，率效应 **+2.12pp**）；③ 无临额组 **+7.82pp**（贡献 **+1.00pp**）。
- **8/17 周**回落主因：离线临额坏账率回落 **2.44pp**（贡献 **−1.25pp**）。
- **8/24 起**持续高位：在线平台化 27~29%（比 8/03 高 10pp）、离线 24~25%、**无临额组升至 37~39% 且份额从 13% → 22%**。
- 反事实：**收缩临额无法消除整体风险，只会把风险转移到无临额长尾客群**。

**怎么调**
1. **不要把"砍临额总量"当主要手段**——它会制造新的长尾风险。
2. 抓手按优先级：**① 矩阵单元收紧（见结论 4）→ ② 离线准入加严（见结论 5）→ ③ 无临额长尾客群专项（多头/共债预警）**。

**预计反馈**
- 结构分解显示：若无临额组份额能从 22% 压回 13%，整体坏账可回落 **≈ 1~1.5pp**（按 8/24 后份额×组间差近似），且不减少放款规模。

### 结论 4｜在线 V5_3 扩额在低分档过度下沉 → 按"矩阵单元"收紧，不要全档关闭

**依据**
- type 迁徙反事实：**41.1% 放款**（25,261 / 61,451）由 V5_2 型 4 变为 V5_3 型 1-3，**加权 t0 29.08%**，新增临额使用 **2.98M 比索**。
- **单元风险（C 组实走 V5_3 vs A 组实走 V5_2）**：g8 tag1 **1,293 笔**（t0 22~35%）、g9 **351 笔**（27~38%）、g10 **541 笔**（其中 score∈[0,1) 段 **t0 42.27%**）。
- 但 **g8/g9 的 score ≥ 3 段 t0 仅 22~27%** → **下沉档内评分仍有排序力**。
- 在线 type1 比例：**V5_2 = 50% / V5_3 = 60%**（V5_3 除放开评级档外，另把最优档比例 +10pp）。

**怎么调**（按矩阵单元，不做全档关闭）
1. **g10**：仅保留 `score ≥ 3` 且**降额**发放；
2. **g9**：`score < 0` 段**停发**；
3. **g8/g9 的 `score ≥ 3` 段**：**保留发放**（t0 仍低）。

**预计反馈**
- 只关掉 **g9 低分段 + g10 非优质档**，可砍掉最差的 **≈ 300~500 笔/窗口**高 t0 发放（g10 单档即 541 笔、t0 42%+）；
- 保留 g8/g9 高分段，**几乎不损失优质增量**（那部分 t0 22~27%，优于大盘）。

### 结论 5｜离线 8/24 客群收紧方向正确，应维持并加严

**依据**
- 准入口径变化：**2026-08-24 前**允许"近 30 天最大逾期 ≤ 2 天"入池（入池占比 **14%~20%**），**之后收紧至 0 天**。
- 离线临额坏账率在 8/10 周跳升 **+5.08pp**（与放松窗口吻合），8/17 周回落 2.44pp。
- 现有准入已含：本包/他包无逾期、他包近 90 天无逾期、年龄 ≤ 65、非禁申、主额度未过期、限定 3 个产品包、有在贷、复贷、距上次临额使用 ≥ 10 天。

**怎么调**
1. **维持 0 天口径**，并把它固化进圈客 SQL（勿回退）。
2. **再加严一档**：对"他包近 90 天无逾期"从计数口径升级为**共债预警**（`curr_ovd_cnt_all`）阈值。

**预计反馈**
- 维持 0 天口径本身已消化了 8/24 前那批 14%~20% 的弱客群；再加严主要影响边缘 5~10% 的入池者，**预计再降离线坏账率 ≈ 0.5~1.5pp**，代价是入池人数小幅下降。

### 结论 6｜同评分段内，有临额客户比无临额客户更优 → 临额是"筛选器"

**依据**
- 同评分段内**无临额组 1T0 显著高于临额组**，即临额政策在**各评分段都筛到了相对优质客户**。
- 临额客户质量显著更优：授信通过率 100% vs 23~28%、放款率 95~97% vs 74~77%、平均合同额近 2 倍。
- **V6_1 拒尾策略在全评分段均有效降低坏账**（非仅低分档）。
- **高风险 type4 客群发放临额后坏账反而下降** → 模型在该客群内仍能筛出优质客户。

**怎么调**
- 把临额定位为**客群筛选与用信提额工具**，而非"纯额度工具"；评估临额效果时**必须区分"持有标签"与"实际使用"**（离线持有 → 使用率约 56.7%，口径见"六"）。

**预计反馈**
- 维持"发临额 + 拒尾"组合，可在不牺牲放款规模的前提下**守住客群质量**；预期整体 1T0 至少不回退（相对"砍临额"方案**少 1~1.5pp 的长尾上行**）。

## 四、不建议做的事（反直觉，避免踩坑）

1. **不要为了压坏账而"砍临额总量"**——结构分解已证明只会把风险转移到无临额长尾（无临额组坏账 37~39%、份额已从 13% 升到 22%）。
2. **不要用"持有离线临额标签"衡量效果**——必须看**实际消耗**；否则会高估临额覆盖（离线实际使用率约 56.7%，历史"≈16%"为旧口径）。
3. **不要把在线临额当作与主额"同池"**——它**在主额池外叠加**，是 1 万上限被突破的唯一原因。
4. **不要按合同 Top-N 样例下结论**（曾误得"溢出笔主额全是 1 万"）——须全量看分布（真实：1 万仅 37.5%）。
5. **不要把 type1 的 50%/60% 混用**——那是 V5_2 / V5_3 的版本差异，不是时间趋势。

## 六、口径与可靠性说明（引用时必带）

- **窗口**：本文金额/笔数均为**复贷老客放款**口径，2026-07-01 ~ 10-15（部分 08-19 ~ 10-05）。
- **在线 vs 离线判定**：唯一判定点 = 本笔 C003 冻结时刻前、本 mid **最近一次临额发放事件**的 `change_event_type`：`C010` → 在线；`C013/C015` → 离线。
- **两类临额不会同时使用**：只要本笔存在 C010，临额使用额恒等于 C010 发放额，离线仅为"持有未消耗"。
- **离线口径冲突已标注**："放款时存在未过期 C015/C013" 口径下使用率 **56.7%**（5,921/10,437），与旧口径"≈16%"差异来自是否含 C013、是否取最新事件及样本窗口——**引用须注明口径**。
- **公式命中率**：在线三段式 99.87%；离线档位公式 96.1%；恒等式 `合同 = 占用主额 + 临额使用` 在线 100% / 离线 99.7%。
- **带"≈"的数字为结构近似**（需正式评估时跑数确认）；其余为实测。
