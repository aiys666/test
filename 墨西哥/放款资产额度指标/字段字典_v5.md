# 放款资产额度指标 v5 字段字典

表：`mx.yj_asset_quota_v5`（v4 改名版，列含义完全一致，只换名）
口径：复贷老客放款笔，2026-09-01 ~ 前一日

**命名规则**：按业务分组加前缀 —— `main_` 主额 / `temp_` 临额池 / `temp_on_` 在线临额 /
`temp_off_` 离线临额 / `avail_` 可用额度口径 / `chk_` 诊断列（不参与业务计算，只用来发现数据问题）。
动词统一：`granted` 发放、`occupied` 占用、`available` 可用、`used` 使用。

---

## 一、标识（7 列）

| 列名 | 中文 | 含义 |
|---|---|---|
| `biz_id` | 进件号 | 主键，一笔放款一行 |
| `mid` | 客户号 | 同一客户多笔会重复 |
| `issue_date` | 放款日 | |
| `release_time` | 放款时刻 | 很多窗口判定以它为锚点 |
| `product_level` | 产品 | 如 C_07_04_00_75 |
| `contract_amount` | 合同金额 | **恒等式左边**：= 主额使用 + 临额使用 + 券 |
| `credit_level_v6_1` | V6_1 主评级 | 1 优 → 11 差 |

## 二、主额 main_（6 列）

| 列名 | 原名 | 含义 |
|---|---|---|
| `main_credit_total` | credit_amount | **授信总额度**（给了多少） |
| `main_occupied_before` | change_used_grantamount | **放款前已被占用的主额**（其他在贷笔占着的） |
| `main_available` | main_available_amount | **放款前可用主额** = 总额度 − 已占用 |
| `main_daily_cap` | daily_max_available_limit | **单日可借上限**（另一道限制，常比可用主额更紧） |
| `main_used` | main_used_this | **本笔实际使用的主额** |
| `chk_main_used_yj` | risk_credit_limit | 诊断：源表口径的占用主额。与 `main_used` 实测 0 笔分歧，仅备查 |

> 关系：`main_credit_total` ≥ `main_available` ≥ `main_used`（放款前可用，不含本笔）

## 三、临额池 temp_（8 列）

> ⚠️ **在线和离线共用同一个额度账户**（`temp_account_id`），额度互相**覆盖**不叠加。
> 所以"总额度/被占用/剩余可用"是**池级**概念，不分在线离线；只有"使用额"才分来源。

| 列名 | 原名 | 含义 |
|---|---|---|
| `temp_total` | temp_acct_total | **临额账户总额度**（这个池子里一共有多少） |
| `temp_occupied` | temp_occupied_by_others | **被其他在贷笔占着的临额**（本笔之前已冻结未释放的） |
| `temp_available` | temp_available | **剩余可用临额** = 总额度 − 被占用 ← 你定义的"剩余可用" |
| `temp_used` | temp_used_this | **本笔实际使用的临额** |
| `temp_source` | temp_source | **来源**：`online` / `offline` / `unknown`（判不出） / `none`（没用临额） |
| `temp_account_id` | temp_limit_main_id | 临额账户号，同一客户在线离线共用 |
| `temp_freeze_time` | temp_freeze_time | 本笔冻结临额的时刻 |
| `chk_temp_available` | temp_available_raw | 诊断：不夹 0 的剩余可用原值，**< 0 说明上游总额度未同步**（实测 6 笔） |
| `chk_temp_used_gap` | temp_used_src_gap | 诊断：yj 与台账的使用额差，≠ 0 说明台账落库延迟（实测 30 笔） |

> 业务例子（你举的那个）：发了 3,000 临额 → 其他在贷笔占着 2,000 → 剩余可用 1,000 → 本笔用 1,000
> 对应：`temp_total`=3000、`temp_occupied`=2000、`temp_available`=1000、`temp_used`=1000

## 四、在线临额 temp_on_（3 列）

| 列名 | 原名 | 含义 |
|---|---|---|
| `temp_on_granted_flag` | tag_1386_self | **本笔是否发放了在线临额** 0/1（风控 1386 节点）|
| `temp_on_granted` | online_grant_amount | **在线弹窗发放额**（客户看到的上限，不管领没领）|
| `temp_on_used` | online_used_this | **本笔使用的在线临额** |

> 在线临额按本笔主额支用算额：`理论额 = floor(主额冻结/20)×20 × 比例`，
> 比例按 type：type1 50%(V5_2)/60%(V5_3)、type2 40%、type3 20%、type4 不发。
> **所以主额支用 = 0 时，在线发放必然 = 0** —— 这是归属判定的第一道硬门槛。

## 五、离线临额 temp_off_（9 列）

| 列名 | 原名 | 含义 |
|---|---|---|
| `temp_off_granted` | offline_grant_amount | **离线批次发放额**（来自 yuhan 发放事实表）|
| `temp_off_used` | offline_used_this | **本笔使用的离线临额** |
| `temp_off_batch` | offline_grant_tag | **批次标签**，如 `0923临额测试组_有在贷_2` |
| `temp_off_batch_date` | offline_data_date | 批次标签日（= 实际发放日 + 1 天）|
| `temp_off_age_days` | offline_grant_age_days | **发放到放款隔了几天**，> 5 即用了超期额度（实测 178 笔）|
| `temp_off_ratio` | offline_grant_ratio_tag | **档位** 10% / 20% / 30%（批次后缀 _1/_2/_3）|
| `temp_off_crowd` | has_outstanding_tag | **圈客人群**：有在贷 / 无在贷 |
| `temp_off_exp_group` | has_temp_tag | **实验组**：临额组 / 减息组 ← 原名严重误导，不是"有没有临额" |
| `temp_off_batch_occupied` | offline_batch_occupied | 批次**快照时**该客户的临额占用（批次口径，会滞后）|
| `temp_off_batch_main` | offline_main_credit_limit | 批次**算额基准** = 主额度，离线发放额 ≈ 它 × 档位比例 |

## 六、可用额度三口径 avail_（4 列）

| 列名 | 原名 | 含义 |
|---|---|---|
| `product_cap` | product_limit_max | 产品单笔上限，常态 10,000 |
| `avail_now` | avail_current_logic | **现行规则下可用** = LEAST( LEAST(可用主额, 单日上限) + 剩余可用临额, 产品上限 ) |
| `avail_no_product_cap` | avail_tochange_logic | **去掉产品上限**后可用 |
| `avail_no_cap` | avail_future_logic | **产品上限和单日上限都去掉**后可用 = 可用主额 + 剩余可用临额 |

> ⚠️ 单日可借上限**只压主额**，临额是叠加在日帽之上的 —— 这是公式里 `LEAST` 套在内层的原因。

## 七、优惠券（2 列）

| 列名 | 原名 | 含义 |
|---|---|---|
| `voucher_amount` | voucher_limit | **额度立减券面值**，用信确认页核销、直接抵减合同额。不是额度、不占临额 |
| `voucher_id` | voucher_id | 券 ID |

---

## 核心恒等式（建表后必验，实测破坏 0 笔）

```
contract_amount = main_used + temp_used + voucher_amount
```

## 来源分流勾稽

```
temp_used = temp_on_used + temp_off_used + (temp_source='unknown' 的 temp_used)
```
unknown 部分单列不吞：yj 有临额使用额，但本笔无在线发放、该 mid 也无离线批次记录。
实测 214 笔 / 78,082 比索，额度来源需找开发确认。
