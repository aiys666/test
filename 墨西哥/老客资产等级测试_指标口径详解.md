## 一、版本与分组标签（口径）

### 1. v3_flag —— 该进件属于哪个资产等级版本

**口径**：按 `app_time`（进件时间）匹配版本上线时间窗，部分窗口内再按 hash 分桶决定归属哪个版本。

**为什么这么算**：资产等级模型是**逐步迭代上线的**，不可能所有用户瞬间切换。所以用"时间 + 随机分桶"把用户平滑过渡到新版本，同时保留老版本对照组。

### 2. daily_max_limit_tag —— 单日可借上限策略的 A/B 分组

**口径**：按进件时间分层 + hash 分桶（阈值 0.5/0.7），标记为 `测试组`/`冠军组`/`v5_2测试组`等。

**为什么这么算**：单日可借上限的调整也是分桶测试，用不同盐值（20251217/20251010）区分不同批次的测试。

## 三、评分卡变量详解（60+个，重点）

评分卡的核心思想：**把连续变量切分成区间，每个区间映射一个分数**。分数是"该区间对客户好坏的贡献度"——分数越高代表越可能是好客户（低风险），越低代表越可能坏。

### 3.1 多头借贷类

#### `advance_duotou_cnt_x_19_score`（近30天多头数）
| 分箱 | 分数 | 为什么 |
|------|------|--------|
| < 2 | 0 | 多头少，正常 |
| 2~4 | 1 | 轻度多头，给正分 |
| 4<x≤6 | -2 | 中度多头，扣分 |
| > 6 | -8 | 严重多头，重扣 |

**口径**：advance 数据近30天内检测到的多头借贷平台数。**多头越多 → 资金越紧张 → 逾期风险越高 → 扣分越狠**。

#### `advance_duotou_cnt_730d_score`（近730天多头数）
| 分箱 | 分数 |
|------|------|
| ≤0 | 0 |
| 0<x≤2 | -1 |
| 2<x≤11 | 0 |
| >11 | -1 |

**为什么这么算**：730天是长期多头，但长期多头未必是坏事（有正常多平台借贷习惯）。所以中间区间(2-11)给0分，只有极端多头(>11)才扣分——说明**短期多头比长期多头更能预示风险**。

### 3.2 逾期类

#### `max_ovd_days_all_score`（历史最大逾期天数）
| 分箱 | 分数 |
|------|------|
| ≤0 | 0 |
| 0<x≤3 | -1 |
| >3 | -2 |

**为什么**：历史最大逾期天数是最强的逾期预测指标。逾期>3天就扣分，因为**逾期过的客户复贷更容易再逾期**。

#### `max_overdue_day_30d_all_score`（近30天最大逾期天数）
| 分箱 | 分数 |
|------|------|
| ≤-999 | -3 |
| -999<x≤0 | 0 |
| 0<x≤1 | -1 |
| >1 | -2 |

**为什么**：近30天逾期比历史逾期更能反映**当前**状态。刚逾期1天的扣1分，逾期>1天扣2分。**-999是缺失值**（无数据），给-3表示"无法确认，按坏处理"。

#### `emcontact_curr_ovd_cnt_all_score`（紧急联系人当前逾期数）
| 分箱 | 分数 |
|------|------|
| ≤0 | 0 |
| >0 | -2 |

**为什么**：紧急联系人逾期 → **社交圈风险传染**。联系人都逾期，说明这个客户身边的人资金状况差，大概率也会逾期。这是**关系图谱风控**的核心变量。

#### `stgy_dyna_amlta_d60_daydiff_median_score`（动态多头60天间隔中位数）
| 分箱 | 分数 |
|------|------|
| <-98 | -1 |
| -98≤x<0 | -2 |
| 0≤x≤15 | -1 |
| 15<x≤25 | 0 |
| >25 | 1 |

**为什么**：多头申请的时间间隔——间隔越短说明**频繁借钱**（越紧），间隔越长越正常。中间(15-25天)是健康区间给0，>25天给正分（很从容）。

#### `stgy_dyna_amlba_d30_f2_daydiff_max_score` / `d21_b_cnt` / `d30_c_cnt` / `d60_f3_cnt`
- `d30_f2_daydiff_max`：30天内两次多头申请的最大间隔 → 间隔<1天重扣(-2)，说明**同一天多头狂借**
- `d21_b_cnt`：21天内B类多头次数 → ≤0扣-2，>0给0
- `d30_c_cnt`：30天内C类多头 → >0扣-1
- `d60_f3_cnt`：60天内F3类多头 → 有就扣分

**为什么**：这些都是**动态多头**（实时更新的多头数据），比静态多头更及时。多头类型不同（A/B/C/F）代表不同风险等级。

### 3.3 行为类

#### `app_loan1_inst_cnt_day7_score`（首贷7天内放款次数）
| 分箱 | 分数 |
|------|------|
| 0 | 1 |
| 1 | 0 |
| 2 | -1 |
| 3~5 | -2 |
| 6~9 | -3 |
| ≥10 | -4 |

**为什么**：首贷后7天内又放款 → **刷贷/资金急用**，次数越多风险越高。0次给+1（很稳），≥10次给-4（极度危险）。

#### `app3_mix_loan1_cfinst_cnt_d30_score`（30天内混合放款次数）
口径与上面类似，但跨3个app。**跨平台频繁放款 = 多头 + 资金紧张**，扣分。

#### `stgy_bj_apply_count_1w_score`（北京一周内申请次数）
| 分箱 | 分数 |
|------|------|
| -98 | 0 |
| 0~2 | 0 |
| 3~7 | -1 |
| ≥8 | -2 |

**为什么**：一周内频繁申请 = **急需钱**。-98是缺失值（无申请记录）给0（不惩罚）。

#### `stgy_bj_apply_jgs_12m_score` / `1w_score`
- `12m`：12个月申请间隔 → =-98或0给-1，>0给0（有间隔记录反而好）
- `1w`：1周申请间隔 → ≥4次给-2（短期频繁申请）

#### `finish_issue_rate_score`（结清率）
| 分箱 | 分数 |
|------|------|
| <0.5 | -2 |
| 0.5~0.7 | -1 |
| 0.7~0.8 | 1 |
| ≥0.8 | 2 |

**为什么**：结清率 = 结清笔数/放款笔数。**结清率高 = 还款意愿好 = 好客户**。这是最强的正向指标之一。

#### `af_uninstall_cnt_30d_score`（30天内卸载App次数）
| 分箱 | 分数 |
|------|------|
| <1 | 0 |
| 1~2 | -2 |
| ≥2 | -3 |

**为什么**：卸载App = **逃避催收**。卸载越多越可能不还钱。

#### `last_repay_gap_days_app_group_score`（距上次还款间隔）
| 分箱 | 分数 |
|------|------|
| ≤0 | -1 |
| 0<x<7 | 0 |
| 7~14 | 1 |
| 14~21 | 1 |
| ≥21 | -1 |

**为什么**：间隔7-21天是**健康的复借节奏**（刚结清又来借，说明有需求且信用好）。≤0(还在还)和≥21(太久不借)都一般。

### 3.4 基础信息类

#### `baseinfo_userprof_age_score`（年龄）
| 分箱 | 分数 |
|------|------|
| 18~36 | -2 |
| 37~55 | 0 |
| >55 | 3 |

**为什么**：年轻(18-36)风险最高（收入不稳定），中年(37-55)最稳，老年(>55)给高分（还款意愿强）。

#### `baseinfo_userprof_degree_score`（学历）
| 分箱 | 分数 |
|------|------|
| ≤3 | -1 |
| =4 | 0 |
| =5 | 1 |
| ≥6 | 3 |

**为什么**：学历越高还款能力越强。注意这里用分数而非绝对值，**不同学历档对应不同还款能力**。

#### `income_score`（收入）
| 分箱 | 分数 |
|------|------|
| =-1 | -2 |
| <10 | 0 |
| ≥10 | 3 |

**为什么**：收入是还款能力核心。收入=-1(未知)扣分，≥10(高收入)给高分。

#### `baseinfo_marry_score`（婚姻）
| 分箱 | 分数 |
|------|------|
| ≤0 | -1 |
| =1(未婚) | 0 |
| =2(已婚) | 1 |
| 3或4 | 0 |

**为什么**：已婚通常更稳定（有家庭责任，还款意愿强）。

#### `baseinfo_has_house_score` / `has_car_score`（房产/车）
- 房产：=3或4给-1（可能是有房贷压力），其余0
- 有车=0给+1，=1给-1

**为什么**：**资产 ≠ 信用**。有车给正分（有资产），但有房可能是有房贷（负资产），所以口径不同。

#### `baseinfo_employee_type_score`（职业类型）
≤3给-2（可能是高风险职业），=4给0，其余0。

## 五、业务标签字段口径

| 字段 | 口径 | 为什么 |
|------|------|--------|
| `main_sanwich_loan_grp` | 首贷/主贷/加贷 | 区分贷款类型 |
| `product_level_change` | 转产线前后产品拼接 | 看产品变化 |
| `change_product_tag` | 是否转产线 | 转产线影响额度 |
| `if_product_or_maxlimit_change_tag` | 产品/上限是否变化 | 前后不一致标记 |
| `other_app_has_loan_tag` | 其他包是否有放款 | 跨app多头 |
| `other_app_has_overdue_tag` / `_interval_tag` | 其他包是否在逾+逾期时长区间 | 跨app逾期 |
| `repayment_clearing_count_tenant_flag` | 租户内结清次数分箱(<3/3-6/6-10/10+) | 还款历史 |
| `if_reloan_24h` | 24h内是否复贷 | 结清后立即复借 |

---

## 六、怎么用这些指标（速查）

1. **看版本效果**：用 `v3_flag` + 转化/贷后字段
2. **看变量区分度**：用 `_score` 变量分组，看各组逾期率是否单调
3. **看多头/逾期影响**：用 `advance_duotou_*`、`max_ovd_*` 等
4. **看策略测试**：用 `*_test_flag`、`*_test_group` 等分组字段
5. **看转产线**：用 `product_level_change`、`change_product_tag`
