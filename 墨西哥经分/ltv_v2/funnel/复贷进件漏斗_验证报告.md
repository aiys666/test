## 二、口径定义

### 2.1 链路（严格嵌套，逐级取交）

| 环节 | 定义 | 单数 |
|---|---|---|
| 进件数 N0 | 复贷进件订单（按 `biz_id` 去重） | 927,963 |
| 前置通过 N1 | `if_sx_passed = 1`（授信/用信决策通过） | 610,122 |
| 后置通过 N2 | N1 ∩ `if_pass = 1`（机审通过） | 595,108 |
| 放款笔数 N3 | N2 ∩ `if_issue = 1`（实际放款） | 589,028 |

### 2.2 三级比率与恒等式

```
前置通过率 r1 = N1 / N0 = 610,122 / 927,963 = 0.657485
后置通过率 r2 = N2 / N1 = 595,108 / 610,122 = 0.975392
用信率     r3 = N3 / N2 = 589,028 / 595,108 = 0.989783

进件数 × 前置通过率 × 后置通过率 × 用信率
  = 927,963 × 0.657485 × 0.975392 × 0.989783
  = 589,028 = 放款笔数       差额 0 ✓
```

分母即上一级的分子，连乘时逐级约分，恒等式**逐行精确成立**（不是近似）。

**为什么必须逐级取交**：原始旗标并不互相包含 —— 机审通过 595,128 单里有 20 单未通过授信，
原始放款 589,068 单里有 40 单不在机审通过集内。直接拿原始旗标相乘会把这部分放大成虚增的放款数；
逐级取交后差额归零。

## 四、口径旁证与不可用的口径

### 4.1 参考列（已进 Excel，**不参与恒等式**）

| 列 | 值 | 说明 |
|---|---|---|
| 参考:原始放款数 | 589,068 | `if_issue` 原始旗标，比嵌套放款多 **40** 单（0.0068%）|
| 参考:进入授信数 | 736,198 | `if_in_sx`，进入授信流程 |
| 参考:机审通过数 | 595,128 | `if_pass` 原始旗标 |
| 参考:复贷模型通过数 | 564,568 | `if_fu_model_passed`，/进件 = 0.6084 |
| 参考:模型通过率 | 0.6084 | |

### 4.2 复贷模型节点是旁支，不是闸口

实测 `if_fu_model_passed`（564,568）与授信通过（610,122）**仅交集 481,699** ——
两者互不包含，无法串进同一条连乘链。故只作参考列。

同理 `if_in_fu_normal_rule_check` / `if_fu_normal_rule_check_passed` 在复贷侧**全为空**
（那是首贷路径的字段），不能用于复贷漏斗。

### 4.3 已核对：本口径与你自己代码里的口径的关系

| 你的既有定义 | 出处 | 本漏斗对应 |
|---|---|---|
| `pre_approval_rate = model_pass_cnt/apply_cnt` | `墨西哥通过率_前置后置.sql` | 参考:模型通过率 = 0.6084 |
| `post_approval_rate = pass_cnt(372)/in_rule_cnt` | 同上 | 后置通过率（口径近似，见下）|
| `confirm_rate = if_in_ruledetermine_data/if_in_confirm` | `墨西哥权责历史数据导出.py` | 用信率（见下）|
| `综合通过率 = 前置 × 用信 × 后置` | `权责自动化处理/reloan_forecast_v6.py:118` | 恒等式同构 |

注：你既有三率的分母不互为上一级的分子（如 `pre_approval_rate` 的分子是模型通过集，
而 `confirm_rate` 的分母是进入用信集），**三者连乘不封闭**，所以不能直接拿去满足这次的恒等式要求。
本漏斗把每一级的分子定义为下一级的分母，因此恒等式精确成立。

## 五、需要你确认的一处判断

**漏斗链本身是数据决定的**：复贷侧唯一嵌套的链是
`进件 ⊃ 授信通过 ⊃ 机审通过 ⊃ 放款`，另外两条候选链都不嵌套（见 4.2），没有选择余地。

**但"前置 / 后置 / 用信"这三个中文名的挂法是我按语义判断的**，依据：

* 你给的顺序是 前置 → 后置 → 用信，本漏斗按此顺序挂：授信通过 → 机审通过 → 放款；
* 挂在最后一档的"用信率 = 放款/审批通过 = 0.9898"语义自洽
  （通过了的人里最终真去提现放款的比例，复贷人群偏高合理）；
* `墨西哥通过率_前置后置.sql` 标题把"前置"与"机审"并列，而它的"后置"取 `order_status=372`（即放款终态）。

若你实际想要的挂法是**前置 = 模型通过率（0.6084）**、或把"用信"放在中间
（用信率 = 机审通过/授信通过 = 0.9754、后置通过率 = 放款/机审通过 = 0.9898），
改法很简单 —— 这只涉及 Excel 表头与 SQL 的别名，**数值列都不用重算**，
因为三级比率与三个计数列都在表里。告诉我一声即可。

## 六、使用提示

1. **维度口径**：渠道取源表 `app_group`（与 `墨西哥LTV代码.sql:11` 的 `r.app_group as app_channel_name` 一致）。
   源表另有 `app_channel` 列，是 UUID，不可读，未用作维度。
2. **比率列可能为空**：某（月/周 × 渠道 × 产品）组合若前置通过为 0，则该行
   前置/后置/用信三率显示为空（分母为 0，数学上无定义），而**不是 0**。
   月度 298 行、周度 1,084 行属此情况，其放款笔数为 0。合计行不受影响。
3. **合计行的比率不是比率求平均**，是「合计分子 / 合计分母」重算（Excel 公式已如此写）。
4. **参考列不要参与连乘**，它们与嵌套口径不等价（见 4.1）。
5. 本漏斗与 LTV v2 两份交付物（月版 / 小金额周版）**相互独立**，两者不要混算。
