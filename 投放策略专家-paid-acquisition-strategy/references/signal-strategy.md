# 回传信号与客群价值策略

> **核心**：你回传什么信号，算法就给你找什么人。回传设计 = 采购需求说明书。只回传安装 → 找爱装 App 的人；回传授信/放款 + 价值 → 找真实好用户。


## 一、事件回传架构

海外现金贷回传事件链：

```
App打开 → 注册 → 进件 → 授信 → 放款 → 首期还款 → 多期还款
   ↓       ↓       ↓       ↓      ↓        ↓          ↓
 低价值信号 ────────────────────→ 高价值信号（但数据稀疏）
```

### 事件选择权衡

| 优化事件 | 数据密度 | 信号价值 | 算法找到的用户 | 典型问题 |
|---------|---------|---------|----------------|---------|
| 安装 | ⭐⭐⭐⭐⭐ | ⭐ | 大量低成本 | 安装即流失，无转化 |
| 注册 | ⭐⭐⭐⭐ | ⭐⭐ | 有初步兴趣 | 不申请，无变现 |
| 进件 | ⭐⭐⭐ | ⭐⭐⭐ | 有借款意愿 | 风控不过，转化中断 |
| **授信** | ⭐⭐ | ⭐⭐⭐⭐ | **通过风控的用户** | 数据量偏少 |
| **放款（推荐）** | ⭐⭐ | ⭐⭐⭐⭐ | **真实产生价值用户** | 回传延迟影响学习 |
| 首期还款 | ⭐ | ⭐⭐⭐⭐⭐ | **高质量还款用户** | 稀疏，需大量才稳定 |
| LTV 回传 | ⭐ | ⭐⭐⭐⭐⭐ | **高价值用户** | 周期长，延迟严重 |

### 分阶段决策

| 预算阶段 | 优化事件 | 逻辑 |
|---------|---------|------|
| 冷启动/小预算（<$30K/月） | 进件或授信 | 保证数据密度让模型学习 |
| 稳量期（$30-100K/月） | **放款** | 追求真实转化 |
| 成熟期（>$100K/月） | 放款 + VBO | 同时回传授信和放款金额做价值优化 |
| 任一事件 < 50 转化/周 | 退一级用上層事件 | 太稀疏模型无法学习 |


## 二、价值信号回传（VBO）

只回传"发生了放款"不够——放款 $50 和 $500 的用户价值差 10 倍。

| 回传方式 | 告诉算法 | 算法行为 | 适用场景 |
|---------|---------|---------|---------|
| 仅放款事件 | "这是个放款用户" | 找最便宜的放款用户 | 限预算、追量 |
| 回传放款金额 | "放款$X的用户" | 找类似放款力度用户 | 成熟期、追规模 |
| 回传授信额度 | "获批$X额度的用户" | 找高额度潜力用户 | 快速积累授信池 |
| 回传预估 LTV | "预期值$X的用户" | 找高 LTV 用户 | 大预算、追质量 |
| **回传实际还款金额（最佳）** | "按时还了$X的用户" | **找真实还款能力好的用户** | 数据充足、追 ROI |

**VBO 要点**：
- Meta 支持 Value Optimization，TikTok 部分支持，Google UAC 通过 tROAS 间接支持
- 建议 ≥100 个价值事件/周才有统计意义
- 回传价值口径变化后需重新训练模型


## 三、回传质量排查

三个致命问题：

| 问题 | 表现 | 影响 |
|------|------|------|
| **数据延迟** | 事件发生后 24h 才回传 | 算法用过期数据优化 |
| **数据缺失** | 部分用户事件没回传 | 算法看到不完整转化漏斗 |
| **数据不一致** | 广告端和业务端口径不同 | 归因混乱、报表对不上 |

**排查路径**：
1. 延迟分布：80% 事件是否在 1h 内到达？< 60% 则有延迟问题
2. 广告端放款数 vs 业务端放款数对比：差异 > 10% 需排查
3. 事件 ID 唯一性：是否有重复回传导致"虚高"转化量
4. CAPI 诊断：使用 Meta Events Manager 查看回传健康度
5. 三方归因对比：Adjust/AppsFlyer 数据与媒体后台是否一致


## 四、Lookalike 种子人群策略

种子人群决定 Lookalike 的天花板：

| 种子来源 | 品质 | 覆盖量 | 策略定位 |
|---------|------|-------|---------|
| 已还款多期用户 | ⭐⭐⭐⭐⭐ | 极小 | 品质定向，适合高客单价 |
| 首期还款用户 | ⭐⭐⭐⭐ | 小 | 还款意愿已验证 |
| **已放款用户（默认推荐）** | ⭐⭐⭐⭐ | 中 | 主力种子，平衡质量与规模 |
| 授信通过未放款 | ⭐⭐⭐ | 中 | 探索定向，原因复杂 |
| 高留存注册用户 | ⭐⭐ | 大 | 放量定向，质量稀释 |

### Lookalike % 矩阵

| 目标 | % | 逻辑 |
|------|---|------|
| 精准获客 | 1% | 质量最高量最小 |
| 标准获客（推荐起点） | 1-3% | 质量与规模的平衡 |
| 放量获客 | 3-5% | 质量稀释但可控 |
| 探索扩展 | 5-10% | 质量明显下降，仅大量需新用户时用 |

**多种子实践**：同时跑 2-3 个不同 % 的 LAL（如 1%+3%+5%），看哪个 CVR 最优。不要同时跑重叠度过高的（1%+2% 互相竞争）。组合优质种子（已放款）+ 增量种子（高留存注册）。


## 五、排除策略

### 优先级排除

| 优先级 | 排除对象 | 原因 | 操作 |
|--------|---------|------|------|
| P0 🔴 | **已放款用户** | 避免重复获客浪费预算 | 回传导出放款用户 ID 到排除受众 |
| P0 🔴 | **已授信未放款用户** | 知道产品但不借，再投浪费 | 建立 7-30 天排除窗口 |
| P1 🟡 | **高频点击不转化用户** | 点击狂魔无转化价值 | 频次控制 + 排除高频点击受众 |
| P1 🟡 | **已卸载用户** | 复装率极低 | 归因工具回传卸载事件 |
| P2 🟢 | **低信用评分代理** | 无法直接获取信用分时用行为代理 | 三方数据源/自定义受众 |

### 再营销 vs 排除

| 用户状态 | 处理 |
|---------|------|
| 已注册，7 天内未进件 | → **再营销**（不同素材提醒），不排除 |
| 已进件但审批未通过 | → **排除** |
| 已放款但逾期 | → **排除** |
| 已还清的老用户 | → **再营销**（独立 Campaign，可复借） |


## 六、客群分层出价策略

现金贷场景中不同客群价值差异极大，需分层出价：

```
Grade 1-2（优质客群）：
  → 价值高、转化难度高
  → 策略：单独 Campaign/Ad Set，出价可比目标 CPS 高 20-30%
  → 优化事件：授信或放款（不追求最便宜，追求精准）
  → 受众：Lookalike 1-2%（已还款用户为种子）

Grade 3（中等客群）：
  → 价值中等、放量主力
  → 策略：主力 Campaign，目标 CPS 出价
  → 优化事件：放款
  → 受众：Lookalike 1-3%（已放款用户为种子）

Grade 4-5（低质/边缘客群）：
  → 价值低、FPD 风险高
  → 策略：预算占比 ≤ 20%，或 Affiliate 低成本获取
  → 优化事件：进件（别为低质用户付放款价获客成本）
  → 受众：宽泛定向或 Audience Network 补量
```

**⚠️ 注意**：Grade 1-2 的 CPS 天然比整体 CPS 高（已验证模式 #001——整体 $16.79 时 Grade1-2 CPS ~$60）。这**不是成本高了**，而是优质用户在全漏斗转化率更低（审核更严）。评估用 **LTV / CAC**，不是只看 CPS。


## 七、CAPI 配置检查清单

CAPI 优先于 SDK——iOS 14.5+ 后 SDK 回传的 ATT 授权率可能低于 30%，CAPI 是唯一可靠通道。

- [ ] 是否启用了 CAPI（Server-side）？还是以 SDK（Client-side）为主？
- [ ] 事件去重逻辑是否配置（Event ID 去重，防 CAPI + SDK 重复计费）
- [ ] 回传事件命名与广告端映射一致？（如 purchase → "放款"）
- [ ] 测试事件在 Meta Events Manager 显示 Active
- [ ] 是否回传了关键参数（value、currency、event_source_url）
